    Шпаргалка: ветки, слияния и публикация

    Короткая памятка к занятию 2. Все действия — в VS Code.

    Термины

    Термин Что это
    Ветка Параллельная линия истории; отдельная от main
    main Главная ветка: только рабочая версия
    Фича-ветка Ветка под одну новую функцию
    Merge Вливание ветки в другую (обычно в main)
    Merge-коммит Точка, где две линии истории сошлись
    Конфликт Git не может решить сам: две ветки изменили одни строки
    Remote (origin) Удалённая копия репозитория (облако)
    push Отправить свои коммиты в облако (ahead)
    pull Забрать чужие коммиты из облака (behind)

    Жизненный цикл фичи (запоминаем!)

    main:  создать ветку feature-xxx
  → коммиты фичи в ветке
  → переключиться на main
  → Merge Branch…: влить ветку
  → Delete Branch…

    Где нажимать

    Действие Как найти в VS Code
    Создать ветку Статусбар (кнопка с именем ветки) → Create Branch…
    Переключить ветку Кнопка с именем ветки → выбрать из списка
    Слить ветку Ctrl+Shift+P → Git: Merge Branch…
    Удалить ветку Ctrl+Shift+P → Git: Delete Branch…
    Граф веток «Источник» → меню «…» → Source Control Graph
    Добавить удалённый репо Ctrl+Shift+P → Git: Add Remote… → вставить URL
    Синхронизация Статусбар → кнопка Sync (push «вверх» / pull «вниз»)

    Смотрим на статусбар перед любым действием

    1. Какая ветка активна — крона любой ошибки: «закоммитил не в ту ветку».
    2. Ahead/behind — «иду на 1 впереди / 2 позади» облака.
    3. Conflict marker в статусбаре → у нас конфликт.

    Конфликт: порядок работы

    1. Панель «Источник» → Merge Changes → появился конфликтный файл.
    2. Открылось окно слияния: Current (главная ветка) / Incoming (то, что вливаем) / Result.
    3. Для каждого участника: «Принять Former», «Принять Incoming», или → обычно всего «Принять все».
    4. Закоммить результат. Готово.

    Помни: конфликт — это вопрос «какой вариант оставить?», а не поломка. Git ничего не потерял: оба варианта на экране.

    Правила веток

    • main — всегда рабочий код. В смелое — только ветки.
    • Одна ветка — одна фича. Не пихай несколько функций в одну ветку.
    • Слил — удали ветку: её история уже в main.
    • Свою «сырую» ветку-эксперимент можно просто не сливать и удалить.

    Публикация на хостинге

    1. На хостинге создать пустой репозиторий (без авто-README!): - пустой README.md не создавать — мешает первому push;
    2. В VS Code: Git: Add Remote… → вставить https://…/repo.git.
    3. Статусбар → Sync. История уплыла в облако.
    4. Правка прямо на сайте (например README через веб-редактор) → Sync — коммит вернулся локально (behind 1 → 0).

    Подсказка: если первый push ругается — проверь, пустой ли репозиторий на сайте (нет авто-README), и что git настроен (имя/почта).
