    Занятие 2. Ветки, слияния, конфликты и публикация

    Сегодня «Генератор паролей» перестанет быть одной линией истории: научимся делать эксперименты, не трогая рабочую версию, соединять готовые фичи в общий код, разбираться с конфликтами и публиковать проект в облако. Всё — через интерфейс VS Code.

    1. Проблема: рабочая версия и «а давай попробуем»

    До сих пор все коммиты шли одной линией: каждый следующий — поверх предыдущего. Хочется добавить смелую фичу, например «оценить сложность пароля». По-старому пришлось бы копировать папку целиком, а результат таскать руками. Копии не соединяются, и в истории таких попыток ничего не видно.

    git решает это ветками — параллельными линиями истории. Можно спокойно «ломать» код в одной линии, пока другая остаётся рабочей, а потом соединить их или отказаться от идеи.

    2. Что такое ветка

    • main — главная ветка. Здесь всегда живёт рабочая версия, сюда попадает только готовое.
    • Ветка — ответвление от какого-то коммита. Коммиты в ветке не влияют на main.
    • Текущая ветка видна в VS Code: кнопка-ветка слева внизу (статусбар).

    Рабочий приём, который пригодится всегда, — фича-ветка:

    1. От main создаём ветку под одну фичу (например feature-score).
    2. В ветке делаем коммиты этой фичи.
    3. Возвращаемся на main и сливаем ветку (merge).
    4. Ветка удаляется — она сыграла свою роль.

    Веток от main может быть несколько одновременно — как веток дерева от ствола:

    * коммит фичи №2               ┐ ветка feature-score
* коммит фичи №1               │
| * коммит в экспериментальной │ ветка feature-score-raw
|/                            ┘
* общая точка расхождения       └ ствол — main

    Почему не коммитить сразу в main

    Так устроена работа с git: main — то, что должно всегда работать, а черновое живёт в ветках до тех пор, пока не станет готовым.

    3. Создаём и переключаем ветки в VS Code

    Создать ветку — нажми кнопку с именем ветки в статусбаре → Create Branch… (или Ctrl+Shift+P → Git: Create Branch…) → введи имя.

    Переключиться — та же кнопка → выбери ветку из списка.

    Важно: переключение меняет код, который лежит на диске: на одной ветке свой main.py, на другой — свой. Запусти программу после переключения и увидишь разницу.

    Главная ловушка новичка

    Смотри, какая ветка активна (имя в статусбаре). Самая частая ошибка — сделать коммиты не в ту ветку и не заметить этого.

    4. Merge — собираем историю в одну

    Когда фича готова, возвращаемся на main и вливаем ветку:

    Ctrl+Shift+P → Git: Merge Branch… → выбери фича-ветку.

    После merge изменения фичи появляются в main. Если пока ты работал в ветке, на main появились свои коммиты (истории разошлись) — результатом станет merge-коммит: точка в графе, где две линии сошлись.

    Слитую ветку удаляют (Git: Delete Branch…). Это не страшно: её коммиты уже в main.

    5. Merge не всегда проходит «автоматом»: конфликт

    Git сливает ветки по строкам. Если две ветки изменили одни и те же строки, git честно признаётся: «я не знаю, какой вариант оставить» — и просит решить вручную.

    • Конфликт появляется в панели «Источник» (Merge Changes).
    • VS Code открывает редактор слияния: Current — что сейчас в main, Incoming — что пришло из ветки, Result — что останется.
    • Для каждого спорного участка жми «Принять текущую/входящую» либо «Принять все» — и merge завершается.

    Конфликт — не ошибка, а вопрос

    Git ничего не сломал. Он показал оба варианта и спросил: «какой оставить?» Если один вариант очевидно хуже — решение лёгкое: оставляем рабочий.

    6. Эксперименты, которые не страшно выбросить

    Ветка-эксперимент живёт по тем же правилам: создал отдельно от main, делаешь коммиты, смотришь результат — и не сливаешь: вернулся на main, и рабочая версия снова как была. Ветку удаляешь — эксперимент исчезает.

    Главное правило модуля

    main — всегда рабочий. Всё смелое — в отдельную ветку: понравилось — слил, не понравилось — удалил без сожаления.

    7. Граф веток (Source Control Graph)

    Историю с ветвлениями удобно читать по графу коммитов: точка = коммит, линии = ветки, слившиеся линии = merge.

    В VS Code граф открывается из панели «Источник» → меню «…» → Source Control Graph (в старых версиях — расширение Git Graph).

    Когда ветки две и они расходятся от одной точки — дерево видно сразу: два «ростка» уходят вверх, а после merge возвращаются в один ствол.

    8. Публикация: удалённый репозиторий

    Проект, который хранится только у тебя на компьютере, легко потерять. Удалённый репозиторий (облако) — вторая полная копия проекта и истории:

    • Бэкап. С ноутбуком что-то случилось — код в облаке цел.
    • Портфолио. Страница репозитория показывает файлы, README и историю коммитов.
    • Командная работа. Несколько человек синхронизируют общую историю (занятие 3).

    Термины:

    Термин Что это
    Remote Удалённая копия репозитория, с которой ты синхронизируешься
    origin Имя первой удалёнки по умолчанию
    push Отправить свои коммиты в облако (ты — ahead, впереди)
    pull Забрать чужие коммиты из облака (ты — behind, позади)

    В VS Code это делается кнопками: настройка удалённого репозитория — Ctrl+Shift+P → Git: Add Remote… (вставь адрес), отправка и получение — кнопка Синхронизировать (Sync) внизу в статусбаре. Состояние ahead/behind подскажет сам git.

    Для публикации создаём на хостинге пустой репозиторий (без авто-README, иначе при первом push будет конфликт).

    9. Проект сегодня

    Одна фича — оценка сложности пароля, две ветки от одного main:

    • feature-score-raw — «наспех» (кривая оценка), 1 коммит: feat: добавил оценку сложности (наспех).
    • feature-score — аккуратная версия, 2 коммита: feat: добавил оценку сложности и feat: добавил пункт «Оценить свой пароль».

    Функция оценки (правильная версия):

    def check_strength(password):
    """Возвращает «слабая», «средняя» или «сильная» для пароля."""
    length = len(password)
    has_digits = any(ch.isdigit() for ch in password)
    has_letters = any(ch.isalpha() for ch in password)
    has_symbols = any(not ch.isalnum() for ch in password)

    score = sum([has_digits, has_letters, has_symbols, length >= 8])

    if score <= 1:
        return "слабая"
    if score <= 3:
        return "средняя"
    return "сильная"

    Пока обе ветки живут, на main появится свой коммит (README) — чтобы merge дал настоящую точку слияния.

    Порядок слияний — наоборот привычного: сначала вливаем «наспех» (чистый merge), потом правильную ветку. Merge feature-score-raw даёт конфликт, потому что обе ветки меняли одни и те же строки меню: в редакторе слияния применяем входящую версию из feature-score (Incoming) — правильную. Итог — в истории остаётся и кривая попытка, и её исправление.

    В конце занятия публикуем «Генератор паролей» в облако: README уже есть (это наш «якорь»), подключаем удалённый репозиторий и синхронизируемся.

    Пора практиковаться

    Всё готово к делу: открой практику занятия 2. Тебя ждут две фича-ветки, честный конфликт в редакторе слияния и первая публикация проекта.
