    Упражнение: ветки, слияния, конфликт и публикация

    На чём работаем: репозиторий «Генератор паролей» из занятия 1 (там должно быть 5 коммитов и действующий main.py). Инструмент: VS Code, панель «Источник» (Source Control).

    Три варианта программы описаны ниже; готовые файлы лежат рядом: 01_password_score_raw.py, 02_password_score.py, 03_password_final.py. Печатаем сами — файлы для проверки и спасения.

    Шаг 1. Якорь на главной: README

    1. Убедись, что активна ветка main (статусбар слева внизу — панель Источник).
    2. Создай в корне README.md и напиши «фантом» — заготовку того, как проект будет выглядеть на хостинге:

    # Генератор паролей

Консольная программа: генерирует случайный пароль, умеет сохранять его
в файл и оценивать сложность.
    3. Коммит: docs: добавил README.

    Теперь на main есть коммит, от которого можно «растить» ветки.

    Шаг 2. Ветка-эксперимент «наспех»

    1. Создай ветку feature-score-raw (Statusbar → Create Branch…).
    2. Добавь в main.py (после функции generate_password) такую оценку:
    def check_strength(password):
    # наспех: оценим только по длине — так тоже бывает
    if len(password) >= 8:
        return "сильная"
    return "слабая"
    1. В main() перед меню поставь строку заголовка и добавь пункт «Оценить свой пароль» (считай, что мы «слёту» добавили сравнимо неверную версию — так на практике бывает):
        while True:
        print("\n=== Генератор паролей ===")
        print("1. Буквы")
        print("2. Буквы и цифры")
        print("3. Все символы")
        print("4. Оценить свой пароль")
        print("5. Выйти")

        choice = input("Выбери действие: ")

        if choice == "5":
            print("Пока!")
            break

        if choice == "4":
            password = input("Введи пароль: ")
            print(f"Сложность: {check_strength(password)}")
            continue

        if choice not in ALPHABETS:
            print("Не понял команду. Попробуй ещё раз.")
            continue

        length = int(input("Длина пароля: "))
        password = generate_password(length, ALPHABETS[choice])
        print(f"Твой пароль: {password}")

        if input("Сохранить в файл? (д/н): ").strip().lower() == "д":
            save_password(password)
            print("Пароль сохранён в passwords.txt.")
    1. Запусти и проверь: для пароля из 2 букв — «слабая», из 10 — «сильная».
    2. Коммит: feat: добавил оценку сложности (наспех).

    Шаг 3. Правильная фича-ветка

    1. Вернись на main (Statusbar → Switch).
    2. Создай ветку feature-score.
    3. Правильная функция — у неё «буквы», «цифры», «символы» и длина:
    def check_strength(password):
    """Возвращает «слабая», «средняя» или «сильная» для пароля."""
    length = len(password)
    has_digits = any(ch.isdigit() for ch in password)
    has_letters = any(ch.isalpha() for ch in password)
    has_symbols = any(not ch.isalnum() for ch in password)
    score = sum([has_digits, has_letters, has_symbols, length >= 8])
    if score <= 1:
        return "слабая"
    if score <= 3:
        return "средняя"
    return "сильная"

    Это одна маленькая единица работы — поэтому делаем отдельный коммит. 4. Коммит 1: feat: добавил оценку сложности. 5. Теперь добавим саму «кнопку»: в меню пункт «Оценить свой пароль» и перенумеруем «Выйти» на 5 — точно так же, как в feature-score-raw. Эталон — 03_password_final.py. 6. Проверь: - abc → слабая; - Abc12345 → средняя; - Abc123!@ → сильная. 7. Коммит 2: feat: добавил пункт «Оценить свой пароль».

    Шаг 4. Смотрим на граф — дерево веток

    Панель «Источник» → меню «…» → Source Control Graph. Видно две ветки: обе растут от main и разошлись. Та же картинка — на графе коммитов.

    Шаг 5. Merge «наспех» (первый, чистый)

    1. Переключись на main.
    2. Ctrl+Shift+P → Git: Merge Branch… → feature-score-raw.
    3. Видишь: влилось сразу. Это fast-forward — история «наспех» просто легла поверх main. Отметь, что конфликта нет.
    4. Проверь и запусти (check_strength по длине). Коммитить не нужно — merge пришёл коммитом.

    Шаг 6. Merge правильной ветки — конфликт!

    1. На main вливаем feature-score.
    2. В «Источнике» появились Merge Changes — конфликт в main.py.
    3. Открывается редактор слияния: - Current — код после feature-score-raw (по длине); - Incoming — код из feature-score (по баллам). - Result — то, что останется.
    4. Для конфликтных строк жми Принять Incoming (правильная оценка должна победить кривую).
    5. Сохрани, закоммить результат (VS Code предложит сообщение Merge).

    Запусти: пункт «Оценить свой пароль» должен давать честную трёхбалльную оценку.

    Шаг 7. Обе ветки уже не нужны

    1. Ctrl+Shift+P → Git: Delete Branch… → удали feature-score-raw и feature-score.
    2. Граф: дерево сжалось в одну линию, но точка слияния осталась — по ней видно, что тут одна ветка была слита в другую.

    Шаг 8. Публикуем проект

    1. На хостинге (GitHub/GitFlic/…) создай пустой репозиторий (не создавая авто-README).
    2. Ctrl+Shift+P → Git: Add Remote… → вставь https://…/repo.git, имя origin.
    3. Статусбар → Sync (или кнопка «Публикация ветки»). История уехала в облако.
    4. Проверь на сайте: файлы, README, граф с merge-коммитом — всё на месте.

    План Б (по LAN): если облака нет, учитель раздаёт команды для создания bare-репозитория — «удалёнкой» станет репозиторий на машине учителя (или у партнёра-«сервера»).

    Шаг 9. Забираем правку с сайта (pull)

    1. На сайте (веб-редактор) поправь README.md, например: 
      Умеет: генерировать, сохранять в файл, оценивать сложность.
    2. Локально твой репозиторий стал «позади» (behind 1).
    3. VS Code → Sync. Правка с сайта приехала, сайт и компьютер снова в одной версии.

    Чек-лист занятия

    • [ ] В графе видно дерево: две ветки от main
    • [ ] Merge feature-score-raw — чистый (fast-forward)
    • [ ] Merge feature-score — конфликт, разрешён Incoming
    • [ ] Обе ветки удалены, но история «кривую» попытку сохранила
    • [ ] Проект опубликован, Sync работает (push и pull)

    Если застрял

    • «Сделал коммиты не в ту ветку» — паника не нужна: Ctrl+Shift+P → Git: Branch… «Ветка содержит коммит X» не ломает ничего. Переключись на правильную ветку и продолжай.
    • «Merge не предлагается / конфликт не появляется» — проверь, что ветки реально разошлись: добавь коммит в main (README) и повтори.
    • «Начал слияние, а в результате какой-то другой main.py» — открыл редактор слияния? Жми кнопки Current/Incoming и сохраняй.
