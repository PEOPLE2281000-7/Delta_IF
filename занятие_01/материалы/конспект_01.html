    Занятие 1. Первый коммит: версии вместо «финал2.py»

    Цель: к концу занятия ты создашь первый репозиторий git и запишешь в него первые коммиты проекта «Генератор паролей».

    Как работаем в этом модуле

    Весь курс — через интерфейс VS Code (панель «Источник» / Source Control). Команды в терминале появятся на занятии 4, когда будет понятен сам смысл операций.

    1. Проблема версий

    Знакомая история? Ты написал программу, она работала. Потом добавил «ещё мелкую фичу» — и всё сломалось. А вернуть назад нельзя: «рабочей» копии уже нет.

    Обычно это решают так:

    main.py
main_2.py
main_2_новый.py
main_final.py
main_FINAL_2.py
main_FINAL_3_исправленный.py

    Это тупик: через неделю ты уже не помнишь, какой файл самый свежий, что менялось от версии к версии и какой из них вообще рабочий.

    Зачем нужен git

    Git решает три проблемы сразу: хранит историю всех изменений, позволяет вернуться к любой версии и позволяет делать параллельные правки, не мешая друг другу (это к занятию 2!).

    2. Как устроен git (простыми словами)

    Представь, что git — это «сохранения в компьютерной игре». Каждый раз, когда ты «сохраняешься» (делаешь коммит), git фотографирует текущее состояние проекта. Один коммит = одна такая «фотография».

    Три места, в которых живёт твой код:

    Место Что это Как называется в VS Code
    Рабочая папка Файлы, которые ты редактируешь «Источник» (Source Control)
    Изменения Файлы, которые ты изменил, но ещё не «сфотографировал» Changes
    Коммиты Проверенные «снимки» проекта Timeline / история

    Порядок любой «сохранёнки»:

    изменил файлы → посмотрел, что изменилось → сделал коммит с сообщением

    Важно: коммит — это осознанное действие. Ты сам решаешь, когда «сохраниться», и сам подписываешь, что именно изменил.

    3. Подготовка: git и VS Code

    Проверяем, что git установлен. Открой в VS Code терминал (меню Терминал → Новый терминал) и выполни:

    git --version

    Если команда не найдена — установи git с официального сайта git-scm.com/downloads и перезапусти VS Code.

    Настраиваем git один раз (git попросит об этом при первом коммите — сделаем сразу, чтобы не отвлекаться):

    git config --global user.name  "Твоё Имя"
git config --global user.email "tvoya@pochta.ru"

    Адрес почты не обязан быть настоящим — это подпись под твоими коммитами.

    4. Создаём репозиторий

    Термин репозиторий — просто «папка, в которой git ведёт историю». Чтобы включить историю для папки проекта:

    1. Открой папку проекта в VS Code (Файл → Открыть папку).
    2. Перейди на вкладку «Источник» (иконка-ветка слева, или Ctrl+Shift+G).
    3. Нажми кнопку «Initialize Repository».

    С этого момента VS Code следит за изменениями в папке. Никаких дополнительных настроек не нужно.

    5. Первый коммит по шагам

    1. Создай файл main.py и напиши первую версию программы.
    2. Запусти её (python main.py) и убедись, что она работает.
    3. Открой панель «Источник». Слева — имя файла, справа — значки + (добавить в коммит) и Discard (отменить изменение).
    4. Нажми + у main.py — файл попадёт в индексацию (это «корзина» для следующего коммита).
    5. В поле сверху напиши сообщение коммита, например: 
      добавил генерацию пароля из букв
      И нажми ✓ Commit (или Ctrl+Enter).
    6. Готово! Первый коммит сделан.

    Как убедиться, что получилось: на этой же вкладке появился список коммитов. Каждый коммит хранит сообщение, автора, время и полный снимок файлов.

    6. Правила хороших коммитов

    Коммит — не «сфоткать всё подряд», а осмысленный шаг:

    1. Один логический шаг — один коммит. «Добавил символы в пароль» — коммит. «Добавил символы и сломал запуск» — уже два шага, такого не делаем.
    2. Коммитим только то, что запускается. Программа падает — сначала почини, потом коммить.
    3. Сообщение короткое и по делу. Начинается с глагола, отвечает на вопрос «что я сделал?».
    Плохо Хорошо
    11111 добавил сохранение паролей в файл
    исправления всякие починил счёт символов в пароле
    рабочая версия добавил выбор набора символов

    Плюс префиксы — они помогают понять тип изменения:

    Префикс Смысл Пример
    feat новая функция feat: добавил пункт «Оценить свой пароль»
    fix починка бага fix: починил падение при пустом вводе
    refactor переделка без новой функции refactor: вынес генерацию пароля в функцию
    docs документация и настройки docs: добавил .gitignore

    7. Diff — что именно изменилось

    После любой правки открой изменённый файл в списке Changes — VS Code покажет diff (разницу с последним коммитом):

    • зелёные строки — добавлено;
    • красные — удалено;
    • жёлтые — изменено (строка переписана).

    Читай diff перед каждым коммитом. Это проверка «я коммичу ровно то, что хочу».

    8. Файлы, которым не место в git. .gitignore

    Запуская программу, ты увидишь в Changes «мусорные» файлы:

    Что Почему не в git
    __pycache__/ байт-код, он пересоздаётся самим Python
    passwords.txt сохранённые пароли — личные данные, а не код

    Чтобы git их игнорировал, создай в корне проекта файл .gitignore (с точкой!):

    # байт-код Python
__pycache__/

# личные данные пользователя
passwords.txt

    Синтаксис простой:

    • * — любое имя (*.pyc — все файлы с расширением);
    • / в конце — папка целиком;
    • # — комментарий.

    Проверка: после сохранения .gitignore мусор исчез из «Источника». Сам .gitignore коммитим всегда (docs: добавил .gitignore).

    9. История и «вернуть назад»

    Посмотреть, что изменилось в коммите: кликни по коммиту — VS Code покажет diff: что убрано (красным), что добавлено (зелёным).

    Вернуть файл к состоянию до правки (отменить изменение): в списке Changes нажми Discard у файла — все несохранённые правки отменятся, файл вернётся к последнему коммиту.

    Важно

    Discard удаляет несохранённые изменения. Закоммиченная история сохраняется всегда — удалить коммит просто так нельзя.

    10. Проект «Генератор паролей» — что делаем сегодня

    Сквозной проект модуля. Каждый работающий шаг — отдельный коммит.

    1. main.py: генерирует пароль из букв → коммит «добавил генерацию пароля из букв».
    2. Добавили цифры и символы → коммит «добавил цифры и символы в пароль».
    3. Меню выбора набора (1–3) → коммит «добавил выбор набора символов».
    4. Сохранение пароля в файл passwords.txt → коммит «добавил сохранение паролей в файл».
    5. .gitignore прячет __pycache__/ и passwords.txt → коммит docs: добавил .gitignore.
    6. Упражнение «сломай и верни»: испорть строку → посмотри diff → отмени (Discard).

    Готовые варианты шагов лежат в папке практики (01_password_letters.py … 04_password_save.py) — как справочник, но лучше печатать код самому.

    Справка по коду. Каждая версия — это маленький шаг:

    import random
import string

print("=== Генератор паролей ===")

length = int(input("Длина пароля: "))
chars = string.ascii_letters + string.digits + string.punctuation
password = "".join(random.choice(chars) for _ in range(length))
print(f"Твой пароль: {password}")

    Так будет выглядеть main.py в конце занятия (меню, выбор набора и сохранение в файл):

    import random
import string

ALPHABETS = {
    "1": string.ascii_letters,
    "2": string.ascii_letters + string.digits,
    "3": string.ascii_letters + string.digits + string.punctuation,
}


def generate_password(length, alphabet):
    """Собирает случайный пароль нужной длины из переданного алфавита."""
    return "".join(random.choice(alphabet) for _ in range(length))


def save_password(password):
    """Дописывает пароль в файл passwords.txt."""
    with open("passwords.txt", "a", encoding="utf-8") as f:
        f.write(password + "\n")


def main():
    while True:
        print("\n=== Генератор паролей ===")
        print("1. Буквы")
        print("2. Буквы и цифры")
        print("3. Все символы")
        print("4. Выйти")

        choice = input("Выбери действие: ")

        if choice == "4":
            print("Пока!")
            break

        if choice not in ALPHABETS:
            print("Не понял команду. Попробуй ещё раз.")
            continue

        length = int(input("Длина пароля: "))
        password = generate_password(length, ALPHABETS[choice])
        print(f"Твой пароль: {password}")

        if input("Сохранить в файл? (д/н): ").strip().lower() == "д":
            save_password(password)
            print("Пароль сохранён в passwords.txt.")


if __name__ == "__main__":
    main()

    Пора практиковаться

    Теория прочитана — самое время сделать своими руками. Открой практику занятия 1 и заведи первые коммиты «Генератора паролей». Конспект никуда не денется — возвращайся к нему по ходу.

    11. Что ты должен уметь после занятия

    1. Объяснить, зачем нужны версии и что такое коммит.
    2. Создать репозиторий в VS Code и сделать коммит с нормальным сообщением.
    3. Прочитать diff (что добавлено, что удалено).
    4. Назвать 4 префикса: feat, fix, refactor, docs.
    5. Написать .gitignore и проверить, что мусор исчез из «Источника».
    6. Отменить незакоммиченную правку (Discard).
    7. Назвать порядок действий перед каждым «сохранением».
