    Шпаргалка: командная работа

    Короткая памятка к занятию 3: clone, общий репозиторий, форк, PR.

    Термины

    Термин Что это
    clone Полная копия репозитория с историей (VS Code: Git: Clone…)
    origin Удалённый репозиторий, с которым работаем (по умолчанию)
    origin/main То состояние, что сейчас в облаке на ветке main
    Колаборатор Человек, которому разрешено пушить в общий репозиторий
    Форк (fork) Личная копия чужого репозитория на твоём аккаунте
    PR (pull request) Предложение влить твои коммиты в чужой репозиторий
    Approve Одобрение PR ревьюером после просмотра diff
    Merge PR Принял изменения — влил в основную ветку

    Синхронизация

    Правило перед любой работой: сначала Sync (pull), потом правь и коммить.

    Sync → ветка feature-… → коммиты → Sync → merge → push → Sync

    Состояние в статусбаре: - 1↓ (behind) — в облаке есть коммиты, которых у тебя нет → Sync; - 1↑ (ahead) — у тебя коммиты, которых нет в облаке → push; - 1↑1↓ — и то и другое: Sync всё уладит.

    Конфликт с чужой правкой

    Когда два человека меняют main.py в одном месте — у второго при merge будет конфликт.

    1. Merge Changes в «Источнике» → конфликтный файл.
    2. Редактор слияния: Current (что было) / Incoming (что пришло).
    3. Решаем: принять свою + вручную подставить чужой фрагмент.
    4. Сохранить, закоммитить.

    Похоже на конфликт занятия 2 — только «враг» уже не ты сам, а коллега.

    Feature Branch Workflow: общий репозиторий

    1. Sync (позаботься о «свежести» main)
2. создать ветку feature-<фича>  (важно: от main!)
3. коммиты → запускать, проверить
4. Sync → переключиться на main → Merge Branch → push → Delete Branch

    Пары: А — feature-multiply, Б — feature-divide. Меняют одно место → у второго конфликт (шаг 4).

    Forking Workflow: форк и PR

    1. На сайте: Fork (создать свой форк чужого проекта)
2. VS Code: Git: Clone → URL СВОЕГО форка
3. ветка feature-level → коммиты
4. push (уходит в форк)
5. На сайте: New Pull Request → base: оригинал ← compare: мой форк/ветка
6. Ревьюер (партнёр): смотрит diff → Approve → Merge

    Меняемся: тот, кто ревьюил — теперь автор своей фичи.

    Частые ошибки

    Ошибка Что делать
    Клонировал чужой репозиторий и сразу пишу Пиши только в свой форк / разрешённую ветку
    Создал ветку от старого main Переключись на main → Sync → создай ветку заново
    Пуш не проходит (нет прав) Ты не колаборатор — вариант: fork + PR
    PR «не вижу diff» Проверь base (оригинал) и compare (форк + ветка)
    В PR попал не мой коммит Сначала Sync, потом ветка; коммить только в фича-ветку

    Полезные команды (занятие 4, а пока для учителя)

    git clone <url>            # копия с историей
git remote -v              # какие удалённые подключены
git push -u origin ветка   # отправить ветку в свой форк
git fetch origin           # узнать про origin, ничего не переключая
