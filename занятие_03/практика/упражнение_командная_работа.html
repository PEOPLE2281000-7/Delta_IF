    Упражнение: командная работа и PR

    Проект: «Математический тренажёр» — учитель выложил его в облако и дал ссылку. Работаем в парах (А и Б). Часть действий делаем по файлам, часть — на сайте хостинга (GitHub/GitFlic/Gitea).

    Программу отдельно не пишем — она уже есть в клоне. Наша задача — git и командные флоу.

    Подготовка: что уже сделал учитель

    • Создал репозиторий math-trainer и выложил в него код (история из 4 коммитов, ветка main).
    • Создал пустой репозиторий для парной работы и добавил вас двоих колабораторами.
    • Приготовил «эталонный» PR-репозиторий (или главный, из которого будет fork).

    Шаг 1. Клонируем «Математический тренажёр»

    1. Ctrl+Shift+P → Git: Clone… → адрес мат-тренажёр от учителя → открой полученную папку.
    2. Проверь в «Источнике»: 4 коммита, есть ветка main.
    3. Запусти python main.py — тренажёр предлагает примеры.

    Как он устроен (чтобы понимать, куда встанут фичи):

    # main.py (фрагмент)
def make_task():
    """Возвращает пример на сложение: (a, b, верный_ответ)."""
    a = random.randint(1, 9)
    b = random.randint(1, 9)
    return a, b, a + b

    Шаг 2. Feature Branch Workflow: общий репозиторий — настройка

    1. На хостинге создай пустой репозиторий math-trainer-<твой ник>.
    2. Ctrl+Shift+P → Git: Add Remote… → имя common, адрес твоего репо.
    3. Нажми Sync (внизу статусбар) или Ctrl+Shift+P → Git: Push — main уехал в твой пустой репозиторий.

    Шаг 3. Фича-ветки в общем репозитории

    Каждый: вернись на main (который синхронизирован), создай свою ветку:

    • А: feature-multiply — в make_task() добавить случайную операцию: иногда «+», иногда «×». Показать вопрос как f"{a} × {b} = ".
    • Б: feature-divide — в make_task() добавить операцию «÷» (составлять так, чтобы ответ был целым: a = b * answer).

    Оба дополняют одно и то же место в main.py! Каждый коммитит свою правку: - А: feat: добавил умножение в тренажёр; - Б: feat: добавил деление в тренажёр.

    Запустите и проверьте свою ветку (вопрос выводится с новой операцией).

    Шаг 4. Первый merge — кто успел

    1. А: переключись на main → Sync (забери чужое) → Git: Merge Branch… → влей свою feature-multiply.
    2. Запусти, проверь — работает.
    3. Push (Sync).
    4. Команда отмечает: «А слил без конфликта».

    Шаг 5. Второй merge — конфликт!

    1. Б: переключись на main → Sync (сейчас приедет и фича А — умножение).
    2. Влей свою feature-divide → появится конфликт в main.py.
    3. Редактор слияния: Current (версия с умножением), Incoming (версия с делением).
    4. Решаем правильно: оставляем обе операции. Incoming для своего фрагмента, Current — для чужого (умножение). Теперь функция умеет и «+», и «×», и «÷».
    5. Сохрани → закоммить → push. Готово: обе фичи в общем репозитории.

    Это «честный» конфликт реальной командной работы: он появляется только у того, кто «пришёл вторым».

    Шаг 6. Forking Workflow: форк и pull request

    1. А (или учитель по очереди) выбирает репозиторий-исходник — например основной math-trainer учителя.
    2. А: на сайте — кнопка Fork. Появится твой форк.
    3. А: Git: Clone… → адрес своего форка.
    4. Создай ветку feature-level: перед вопросом спрашивай уровень сложности (1 — числа 1–9, 2 — числа 10–99). Пример:
    level = int(input("Уровень (1 или 2)? "))
limit = 9 if level == 1 else 99
a = random.randint(1, limit)
    1. Запусти, проверь, коммить: feat: добавил выбор уровня сложности.
    2. Push (уйдёт в твой форк), на сайте → New Pull Request: - base: исходный репозиторий, ветка main; - compare: твой форк, ветка feature-level.

    Шаг 7. Ревью и merge

    1. Б — ревьюер: открываешь PR (ссылка пришла или на сайте), читаешь Files changed (diff!).
    2. Оставляешь комментарий (хотя бы один вопрос) → Approve.
    3. А: отвечаешь на комментарий → видишь «Approved» → Merge pull request.
    4. Проверьте: изменения влились в main исходного репозитория. Смена ролей (если время): теперь Б делает фичу через форк, А ревьюит.

    Чек-лист занятия

    • [ ] Клонировал чужой репозиторий и увидел историю в «Источнике»
    • [ ] В Feature Branch Workflow: обе фичи (умножение и деление) в общем репозитории
    • [ ] Конфликт со второй фичей решён через редактор слияния (обе операции сохранились)
    • [ ] Сделал форк и клонировал СВОЙ форк
    • [ ] PR отправлен, ревьюер написал/поставил Approve, PR merge
    • [ ] Перепроверил: Sync/пул перед новой работой

    Если застрял

    • «Не знаю, куда пушить: в форк или в исходник?» — всегда вдоль своей ветки: в свой форк (Forking Workflow) или в общий репозиторий (Feature Branch Workflow). Исходник чужого репо не трогаем руками.
    • «Конфликт с чужой фичей» — это нормально (шаг 5): договариваемся, какая часть чья, и собираем в редакторе.
    • «PR не вижу diff» — проверь стрелки base/compare: base — исходный репо, compare — твой форк и ветка.
    • «Клонировал не форк» — clone из адреса твоего аккаунта: https://…/<твой_ник>/….
