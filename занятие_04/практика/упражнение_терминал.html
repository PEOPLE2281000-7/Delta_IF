    Упражнение: команды в терминале

    На чём работаем: личный репозиторий «Генератор паролей» из занятия 2. В конце проведения будет конфликт — разреши его маркерами руками.

    Открой в VS Code терминал (меню Терминал → Новый терминал). Все команды вводим без кавычек-«ёлочек», с обычными прямыми кавычками в -m.

    Шаг 1. init — репозиторий в один вызов

    1. Создай новую пустую папку warmup, открой её в VS Code.
    2. В терминале: 
      git init
      git сообщит, что создал пустой репозиторий. git status покажет «On branch master/main» и список команд подсказки.
    3. Коммитов пока нет — это просто знакомство. Пустая инициализация — легитимное состояние репозитория.

    Здесь мы сдаём на репозиторий «Генератора паролей». Вернись к его папке (Файл → Открыть папку) и продолжай.

    Шаг 2. status и log — «что происходит»

    В папке «Генератора паролей»: 

    git status
git log --oneline

    Убедись: твоя история (5–7 коммитов из занятий 1–2) читается как список. Потом: 

    git log --oneline --graph --all
    Увидишь дерево: где-то есть точка «Merge branch 'feature-score'» — она и есть слияние из занятия 2.

    Шаг 3. Ритуал add → commit

    1. В main.py добавь после меню «пункт про справку» (например, при вводе 0 выводится короткая подсказка про меню):
    if choice == "0":
    print("1–3 — набор символов, 4 — оценка пароля, 5 — выход.")
    continue

    И в меню print("0. Справка").

    1. Запусти — работает.

    2. Терминал, по порядку: 

      git status
git diff main.py
git add main.py
git commit -m "feat: добавил справку по меню"

    3. git log --oneline — новый коммит сверху.

    Шаг 4. Ветки в терминале

    1. git branch — видишь * main.
    2. Создай и перейди: 
      git switch -c spice-cleanup
    3. git branch — звёздочка на spice-cleanup.
    4. В этой ветке сделай микрофичу: измени заголовок меню print("\n=== Генератор паролей ===") — добавь метку версии: print("\n=== Генератор паролей (v2) ==="). Запусти — программа работает. Коммить: 
      git add main.py
git commit -m "refactor: уточнил заголовок меню"
    5. git log --oneline --graph --all — увидишь, что новая линия ушла в сторону.
    6. Вернись на main: git switch main. Теперь настоящий командный сценарий: пока ты работал в ветке, на main «появилась» своя правка. Прямо после той же строки заголовка добавь разделитель, чтобы обе правки легли в одну строку: 
          print("\n=== Генератор паролей ===")
    print("-" * 40)
      Закоммить feat: добавил разделитель в меню.

    Шаг 5. merge и конфликт по маркерам

    1. Ты на main; ветка spice-cleanup изменила строку заголовка, а main — ту же строку (добавил разделитель после неё). Обе ветки задели одно и то же место, значит будет конфликт: 
      git merge spice-cleanup
      git остановится и напишет, что merge не удался.
    2. Открой main.py — в заголовке меню появились маркеры: 
      <<<<<<< HEAD
    print("\n=== Генератор паролей ===")
    print("-" * 40)
=======
    print("\n=== Генератор паролей (v2) ===")
>>>>>>> spice-cleanup
    3. Разреши руками: оставь оба улучшения — и метку (v2), и разделитель, — удали маркеры <<<<<<<, =======, >>>>>>>: 
          print("\n=== Генератор паролей (v2) ===")
    print("-" * 40)
    4. Сохрани файл, python main.py — работает.
    5. Заверши merge: 
      git add main.py
git commit            # git подставил готовое сообщение "Merge ..."
    6. git log --oneline --graph — merge-коммит на месте.
    7. Удали слитую ветку: git branch -d spice-cleanup.

    Шаг 6. restore — вернуть незакоммиченное

    1. Испорть строку: удали break из обработки choice == "5".
    2. Сохрани, git status — изменение видно.
    3. git restore main.py — файл вернулся к последнему коммиту.
    4. Запусти — меню снова с break. (Если спешишь — пропусти, суть та же, что Discard.)

    Шаг 7. remote (если есть куда пушить)

    git remote -v
    Если адрес origin есть — проверь git push origin main (обнови своего хостинговый клон). Если нет — просто «напомни себе», что push/pull — два слова вместо одной кнопки Sync.

    Чек-лист занятия

    • [ ] git init создал репозиторий в пустой папке
    • [ ] История читается через git log --oneline --graph --all
    • [ ] Ритуал status → diff → add → commit выходит без ошибок
    • [ ] Ветка создана и переключена через switch -c; удалена через branch -d
    • [ ] Конфликт разрешён вручную по маркерам <<<<<<< / ======= / >>>>>>>
    • [ ] restore вернул файл к последнему коммиту

    Если застрял

    • «Команда не найдена» — git не в PATH; переустановите git и перезапустите VS Code.
    • Git открыл vim — как выйти? — :q! + Enter (без сохранения) либо :wq (сохранить текст для удачного merge).

    Шаг 5 — честный: конфликт появляется осознанно, чтобы потренировать маркеры. На занятии 2 мы решали его кнопкой Incoming — теперь делаем это вручную.
