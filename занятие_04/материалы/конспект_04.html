    Занятие 4. Команды в терминале: что на самом деле жмёт VS Code

    Три занятия мы работали кнопками. За каждой кнопкой стоит текстовая команда — сегодня снимем «завесу интерфейса» и сделаем привычные операции руками, в терминале. Работаем на личном репозитории «Генератора паролей».

    1. Зачем терминал, если есть кнопки

    Кнопки VS Code — это «упаковка» для текстовых команд git. Ситуации, когда текстовая команда незаменима:

    • Скрипт / автоматизация — например, «проверить историю перед сдачей» одним вызовом.
    • Чужая инструкция — 80% туториалов и ответов дают команды, их надо уметь прочитать.
    • Решение нестандартных случаев — GUI показывает не всё; терминал показывает всё.

    Важно: смысл операций ты уже знаешь. Терминал — не новый материал, а другой способ говорить то же самое. Точки соответствия:

    Кнопка в VS Code Команда git
    Initialize Repository git init
    Statusbar / Changes git status
    + у файла (stage) git add <файл>
    ✓ Commit git commit -m "сообщение"
    История (Views / Timeline) git log --oneline --graph --all
    Создать ветку git branch <имя>
    Переключить ветку git switch <имя>
    Merge Branch… git merge <ветка>
    Discard git restore <файл>
    Sync (push) / Sync (pull) git push / git pull
    Clone git clone <url>

    2. Первые команды: status, add, commit

    Открой в VS Code терминал (меню Терминал → Новый терминал), папка должна быть та, где репозиторий.

    git status — ответ на «что происходит прямо сейчас». Показывает, какие файлы изменены (в рабочей папке), какие уже добавлены в коммит (staged), на какой ты ветке:

    $ git status
On branch main
Changes to be committed:        ← уже добавлено (staged)
        modified:  main.py

Untracked files:                ← новые файлы, git их ещё не видел
        data.txt

    git add <файл> — кнопка «+» одним вызовом. Можно и всё разом: git add . (но сначала посмотреть на git status!).

    git commit -m "сообщение" — кнопка ✓. -m значит «сообщение в кавычках». Привычка: сначала git diff (что меняю), потом add+commit.

    Минимальный ритуал, который ты теперь можешь делать из командной строки:

    # 1. что изменилось
git status
git diff main.py
# 2. готовим файл(-ы) и сохраняем
git add main.py
git commit -m "feat: добавил счётчик попыток"

    git соберёт коммит

    Если забыл -m "…", git откроет текстовый редактор (vim). Самый простой выход без сохранения — :q! + Enter. Проще не забыть -m.

    3. git log — читаем историю

    git log --oneline — однострочная история: каждый коммит занял одну строку.

    $ git log --oneline
a3f2c19 feat: добавил счётчик попыток
84bd01b docs: добавил .gitignore
1c9e0aa feat: добавил сохранение в файл

    А git log --oneline --graph --all — то же самое, но ещё и дерево веток (линии и звёздочки merges). Это ровно то, что показывал Source Control Graph, только текстом:

    * 3d33e05 Merge branch 'feature-score'
|\
| * 2ab12cd feat: добавил пункт «Оценить свой пароль»
| * 9f0a07b feat: добавил оценку сложности
|/
* c4e9d11 docs: добавил README

    4. Ветки в терминале: branch, switch, merge

    Чтобы Команда
    Увидеть ветки (звёздочка — активная) git branch
    Создать ветку git branch feature-<имя>
    Создать И переключиться git switch -c feature-<имя>
    Переключиться git switch <ветка>
    Слить ветку в текущую git merge <ветка>
    Удалить слитую ветку git branch -d <ветка>

    Проверяй, какая ветка активна — git branch покажет * main.

    5. restore — «вернуть назад»

    git restore <файл> — тот самый Discard: отменить изменения, вернуть файл к состоянию последнего коммита.

    git restore main.py

    Стоп-крана нет

    restore безвозвратно отменяет незакоммиченные правки. Закоммиченное не трогает — для отката коммита (вне курса) есть git reset/git revert.

    6. Конфликт в терминале: маркеры

    При merge с конфликтом git не открывает красивый редактор — он печатает маркеры прямо в файл:

    def check_strength(password):
<<<<<<< HEAD
    if len(password) >= 8:            ← что было на текущей ветке
        return "сильная"
    return "слабая"
=======
    score = sum([has_digits, has_letters, has_symbols, length >= 8])   ← что пришло из ветки
>>>>>>> feature-score

    Разбирать так, как на занятии 2, просто вручную:

    1. <<<<<<< HEAD — начало «моего» куска и всё до ======= — вариант текущей ветки. /~~~~~ — разделитель; от него до >>>>>>> имя-ветки — пришедший вариант.
    2. Удали маркерные строки и один из вариантов, оставь правильный, сохрани файл.

    После ручной правки — git add <файл> и git commit -m "merge: разрешил конфликт" (или просто git commit, git предложит готовое сообщение).

    7. Remote: push / pull / clone

    То же, что Sync — только адресно:

    git remote -v            # кто наши «удалёнки»
git push origin main     # отправить ветку main в origin
git pull origin main     # забрать и влить изменения из origin/main
git clone <url>          # скопировать репозиторий с историей

    Разница push/pull: push отдаёт свои коммиты, pull забирает чужие. В статусбаре VS Code обе эти операции были одной кнопкой Sync — возьми за привычку делать их и терминалом.

    8. Итог: терминал — тот же git

    Карта «кнопка → команда» (таблица выше) — вся, что нужна в этом курсе. Остальные команды (reset, revert, rebase, stash) — это уже следующий шаг, за пределами краткого курса, но инструмент предсказуемый: любая «кнопка» в VS Code имеет текстовый двойник.

    9. Проект сегодня

    Сегодня возвращаемся к личному «Генератору паролей»: повторяем весь путь командами — от git init до ручного разрешения конфликта по маркерам. Проект тот же, меняется только способ управления.

    Пора практиковаться

    Терминал ждёт. Открой практику занятия 4 и проделай знакомые операции словами: status, add, commit, ветки, merge и конфликт.
