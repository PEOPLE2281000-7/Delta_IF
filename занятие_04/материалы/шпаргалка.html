    Шпаргалка: команды в терминале

    Полная карта «кнопка VS Code → команда git» и порядок работы из командной строки.

    Карта «кнопка → команда»

    Кнопка в VS Code Команда git
    Initialize Repository git init
    Statusbar / Changes git status
    + у файла (stage) git add <файл>
    + файлов («всё») git add .
    ✓ Commit git commit -m "сообщение"
    История git log --oneline --graph --all
    Создать ветку git branch <имя>
    Создать и переключить git switch -c <имя>
    Переключить ветку git switch <имя>
    Список веток (* — активная) git branch
    Merge Branch… git merge <ветка>
    Удалить слитую ветку git branch -d <ветка>
    Discard (отменить правку) git restore <файл>
    Sync (push) git push origin main
    Sync (pull) git pull origin main
    Clone git clone <url>
    Список удалённых git remote -v
    Что изменил в файле git diff <файл>

    Ритуал коммита из терминала

    git status            # что происходит сейчас
git diff main.py      # что именно я меняю
git add main.py       # готовлю файл
git commit -m "feat: добавил …"   # сохраняю

    Порядок и смысл те же, что и с кнопками. Не забудь -m — иначе git откроет текстовый редактор (выход: :q! + Enter).

    git log — читаем историю

    git log --oneline                          # каждый коммит — строка
git log --oneline --graph --all            # + дерево веток и точки слияний

    Ветки

    git branch                            # какие ветки, где я
git switch -c feature-score          # создать И перейти
git merge feature-score              # влить в текущую
git branch -d feature-score          # удалить слитую

    Всегда проверяй активную ветку (git branch) перед merge.

    Конфликт по маркерам

    В файле, если git не смог решить:

    <<<<<<< HEAD
<вариант с текущей ветки>
=======
<вариант из вливаемой ветки>
>>>>>>> feature-score

    Что делать:

    1. Строки между <<<<<<< и ======= — было здесь.
    2. Между ======= и >>>>>>> — пришло из ветки.
    3. Убрать лишний вариант и все три маркерные строки.
    4. Сохранить → git add main.py → git commit (git предложит сообщение merge).

    restore: вернуть незакоммиченное

    git restore main.py

    Отменяет только несохранённые правки. Закоммиченная история не трогается.

    Remote

    git remote -v            # кто наши «удалёнки»
git push origin main     # отправить своё
git pull origin main     # забрать чужое
git clone <url>          # копия репозитория с историей

    Правило из занятия 3 не отменяется: Sync перед началом работы, потом в свою ветку.

    Частые вопросы

    Вопрос Ответ
    «Команда не найдена» git не установлен / не добавлен в PATH — переустанови и перезапусти VS Code
    «Не помню точное имя команды» git --help или git log -h
    «git открыл vim, как выйти?» :q! + Enter — выйти без сохранения
    «git merge открыло редактор с сообщением» Выйти через :q (сохранить сгенерированный текст) — оставить как есть
    «restore вернул не то» restore трогает только незакоммиченное; ещё живее — git stash, вне курса
